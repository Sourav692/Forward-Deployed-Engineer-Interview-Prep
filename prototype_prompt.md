# Build a Functional Dummy Prototype of the Forward Deployed Learning Platform

You are working inside the `Forward-Deployed-Engineer-Interview-Prep` repository.

Build a functional, clickable prototype of the learning platform described in `00_Start_Here/Platform_Blueprint.html` (revision 3). The product is **Forward Deployed**, with the tagline "Applied AI engineering, from the customer's problem to production, and the interview that tests both."

This is **not** the production platform. The goal is to demonstrate the complete user experience using clearly labelled sample data:

- information architecture and navigation;
- learning flow (tracks, sections, modules, lessons, exercises, checkpoints);
- projects, assessments and interview practice;
- progress tracking, readiness scores and the dashboard.

Do not build a backend, database, real authentication, payments, or the final curriculum.

## 5. Required interactions

Implement all of these with client state persisted to localStorage under `fd:demo:v1:*`. Wrap every storage read and write in try/catch, and render correctly when storage is blocked by showing a "Progress won't be saved in this browser" notice. Reuse the probe pattern from `src/lib/storage.ts`.

**Learning flow:**

- Start a track (choosing a path sets the recommended sequence), continue a track, and expand or collapse sections.
- Open a module, a lesson and an exercise. Mark lessons and exercises complete.
- Take a checkpoint, see the score, and retry it.
- Take a mock and self-score it. Take the readiness exam, simulated.
- Progress rolls up from lessons to modules, sections, tracks and the path. Weight rollups by estimated minutes.

**Prerequisite gating** (soft):

- Show the Blocked status and a prerequisite check card.
- Passing the prerequisite checkpoint clears Blocked automatically.
- "Open anyway" works.

**Status rules** (blueprint §16):

| Status | Rule |
|---|---|
| Completed | Lessons read, checkpoint at 70% or above, and the required exercise submitted |
| Mastered | Passed twice, at least 7 days apart, with confidence 4 or above. Simulate the date with a "time travel" demo control in settings. |
| Needs revision | Set when confidence is 2 or below, a checkpoint fails, or 14, 30 or 60 days pass since the last pass |
| Skipped | Set from the path picker or a "Test out" action; counts as done but adds no readiness evidence |

**Readiness scores** (shown with the weakest dimension named):

- **Interview readiness:** 35% worksheet and rubric means + 30% mocks + 20% checkpoint pass rate + 15% behavioural readiness. Reading counts zero.
- **Portfolio readiness:** 40% capstone rubric + 30% projects completed + 20% write-up + 10% story-to-project links.

**Revision queue:** items enter and leave by the rules above. "Review now" re-opens the item, and rating confidence 4 or above removes it.

**Bookmarks and history:** bookmark lessons, questions, projects and cases. Mark questions reviewed, set confidence (1–5) per module and question, and add notes to modules and lessons.

**Filtering:**

- Tracks: level, topic, required or optional.
- Projects: type, difficulty, skill, status.
- Questions: hub, category, difficulty, reviewed, bookmarked.

**Search:** a ⌘K dialog searching tracks, modules, lessons, projects, questions, cases and glossary terms. Reuse or extend the pattern in `src/components/SearchDialog.tsx`, with the index built from the demo data, not `/search-index.json`.

**Projects:** update project status, add a GitHub repository placeholder, and tick the deliverables checklist.

**Dashboard planning:** a weekly hours budget in settings drives the dashboard's "finish by" date, using the study-plan days-to-finish model.

**Portability:** a JSON export and import of demo progress, and a "Reset demo data" action that restores the seeded state, behind a confirmation dialog.

**Feedback states:** recent activity updates live. Show success toasts, blocked and error states (for example invalid import JSON, or a checkpoint submitted with unanswered questions), and empty states.

**Persistence:** progress survives a page refresh.

## Acceptance criteria

The prototype is complete only when a user can do all of the following.

**Browse and learn:**

1. Open `/demo` and understand the product, its audience and its six areas.
2. Pick a path from the diagnostic, or choose a company variant, and see the recommended sequence.
3. Browse all ten tracks with required, optional and skipped states, and filter them.
4. Open a track and see its sections, modules, projects and checkpoints.
5. Open a module and its lessons, complete lessons, and see progress roll up to the module, track and dashboard.
6. Complete an exercise through a simulated submission and self-evaluation.
