# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout

- Root dirs (`FDE/`, `Case_Study_Groups/`, `Last_Day_Prep/`, `Handbook/`, …) are markdown prep content. Only `FDE/`, `Case_Study_Groups/`, `Last_Day_Prep/` and `Blitzy_Prep/` feed the site.
- `site/` is the only JS project: Next.js 16 App Router, React 19, Tailwind v4, npm. Run all npm commands from `site/`. No root package.json.
- Next 16 APIs may differ from training data. Read `site/node_modules/next/dist/docs/` before using Next APIs (see `site/AGENTS.md`).
- `FDE/Complete GEN AI FDE Interview System — Core + GenAI/` has an em-dash and spaces: always quote it in shell commands.

## Commands (from `site/`)

- `npm run sync`: regenerate `site/content/` from root sources. Runs automatically before `dev` and `build`.
- `npm run check:content`: the de facto test suite (no test runner exists). Validates worksheet structure, editorial metadata, internal links, glossary acronyms, placeholders. Run after any content, `editorial.ts`, `glossary.ts` or sync-script change.
- `npm run lint`, `npx tsc --noEmit` (no typecheck script; `tsconfig.json` excludes `scripts/`).
- `check-parse.ts` runs as plain `node` via native TS type-stripping: needs a recent Node.

## Content pipeline

- `site/content/` and `site/public/fde-last-day-prep/` are generated by `site/scripts/*.mjs` but committed (Vercel root is `site/`, so the build cannot see root sources and uses the snapshot). Never hand-edit them: edit the root source, then `npm run sync`.
- Sync does `rm -rf content/` and rewrites `generatedAt` in `manifest.json`, so every dev/build run dirties `manifest.json`.
- Root `Handbook/`, `Study_Guides/`, `Question_Banks/`, `OpenAI_Applied/`, `Supplementary_Guides/` are not synced to the site.
- Worksheets have no frontmatter. Fillable regions are inferred from emptiness (empty table cell, bare `-` bullet, `Label:` with nothing after). Metadata lives in `site/src/lib/editorial.ts`.
- `site/src/lib/editorial.ts` and `glossary.ts` are imported by the `.mjs` sync scripts: keep them free of runtime imports.
- Track, tab and slug ids must never change (URLs and localStorage progress `fd:v1:*` key on them); labels may change. Track ids must be unique site-wide.
- An all-caps token on 3+ pages must be added to `GLOSSARY` or `NOT_ACRONYMS` in `glossary.ts`, or `check:content` fails.
- Adding a module/track/scenario touches many files: use the `/add-module` skill.

## Blitzy / module 16

- `Blitzy_Prep/` is gitignored on purpose, but its generated snapshot in `site/content/modules/16-company-oriented-prep/` is committed and deployed as the public Blitzy Prep section.
- The public site contains 11 Blitzy guides at `/modules/16-company-oriented-prep`. Treat the root source as private working material and the generated snapshot as the deployable copy.
- `company-prep.mjs` reads `Blitzy_Prep/` when available. In clones without it, `sync-content.mjs` preserves the committed company-prep snapshot so Vercel builds still succeed.
- `Blitzy_Prep/01_Code_Review_Bug_Drills.md` is the source of truth; the `.ipynb` is a derived practice copy. Sync reads only the `.md`.

## Git and deploy

- The active Vercel project is `forward-deployed`; production is https://forward-deployed-sigma.vercel.app/. The former `site` project and `site-sourav-dbx.vercel.app` deployment were deleted.
- Vercel deploys `main` to production on push; other branches get preview URLs. Never push to `main` directly: work on a branch, open a PR, merge.
- Commit messages use conventional prefixes: `feat:`, `content:`, `fix:`, `chore:`.
- Style guide for content: `site/specs/2026-09-27-content-architecture-and-editorial-style.md`.
