Four constraints on every support turn

Design a gateway for a customer-support agent that survives a provider outage without customer-visible downtime, resists prompt injection and personally identifiable information (PII) leaks, spends less than $500 per day, and keeps p95 latency below three seconds. P95 means 95% of the measured requests finish within that time. The first discovery question is what counts as finishing: the first streamed token or the complete answer.

A gateway is the shared path through which model traffic passes. It screens, meters, routes and recovers each call. A customer message may trigger an agent turn with several model and tool steps. Screening only that message leaves the later paid calls outside the budget and recovery controls.

This case is for engineers preparing for Forward Deployed, solutions and applied AI interviews. It assumes familiarity with model APIs, token pricing, API gateways, retries and circuit breakers. Work through the dollar arithmetic before reading the solution, then rehearse the design and cost pivot. The target is an explainable design, not a deployed gateway. The source is a mock design built from a production and operations tutorial: its prompt, seven-point rubric and strong-answer outline supply the constraints. Pricing, latency and residency receive further worked treatment here.

All model names, prices, durations and traffic assumptions below belong to the captured case. They are historical whiteboard inputs, not current vendor offers or measured service guarantees. The captured reference reports its price check as 27 September 2026. No current price verification is claimed.

Trace a support request

Consider an illustrative customer asking a support question that includes an account number. Authentication identifies the session and policy assigns its data class. The input guard masks PII before cache lookup or any provider call. A safe FAQ cache hit can answer immediately after output validation. Live account answers bypass reusable caching.

On a miss, the gateway counts tokens, checks budget admission, classifies complexity and checks intent. A simple turn takes a small-model route. An agent turn may make five calls, each admitted and metered through the model face. A failed provider moves the request to an allowed fallback only while time and budget remain. The customer receives a validated answer with its model source, a labelled degraded response, or a human handoff. An agent instead receives a typed failure when no trustworthy model response is available.

1. Place the gateway on both sides of the agent

The edge face screens customer input and final agent output. The model face sits between every agent or evaluator call and its provider. The source playbook estimates that one user request can become 5 to 20 sub-requests. Budget enforcement at the edge alone therefore misses most of an agent's spend and leaves later failures unrecovered.

One source-reported research platform uses a shared sidecar: agents ask for a function, and configuration maps that function to a provider. When a provider changes, the team changes one mapping rather than provider code in five places. This is the shared function-to-model layer a platform can extend to further agents.

Ask the five questions in the table before drawing. The case assumes 10,000 daily users and three turns each, one customer across several regions, and a prohibition on PII reaching an unauthorised customer or provider. Residency remains an explicit discovery question. Use first token for multi-step turns and full answer for one-call turns only after agreeing that interpretation with the interviewer.

The action-authorisation gateway described in the source's Customer Support Automation reference has another job: deciding which actions an agent may take. A real support product may need both. The model traffic gateway described here does not grant refund or booking authority.

2. Make each constraint fail a test

Turn each requirement into a test and assign an owning component. During a single-provider outage, every customer response must be answered, labelled as degraded, or handed off. That is a useful availability test. It does not establish that all outages can produce an equivalent model answer.

The latency targets are p95 under three seconds to first token on every turn and to full answer on one-call turns. Enforce the daily $500 ledger before admission. The illustrative per-call input cap is 8,000 tokens. Reject an oversized call explicitly rather than silently truncating context.

Version the red-team suite and block release when a known attack passes through input or output checks. This is a finite regression requirement. It cannot establish zero residual injection risk. Apply PII policy to responses and logs, tag every answer with model and provider, and retain enough trace information to reconstruct guard decisions, route, tokens and cost.

Safe caching, region routing, real-path red teaming and versioned configuration make these requirements operable. The tables connect each requirement to a component, so an interview answer can name who enforces it.

3. Calculate the $500 day

Use 30,000 turns a day: 10,000 users multiplied by three turns. A 30% cache hit rate removes 9,000 generation paths. Of 21,000 misses, 70% are simple one-call turns and 30% are complex five-call turns. Five calls is the low end of the source's 5 to 20 sub-request rule. Each call has 2,000 input and 250 output tokens.

At the historical illustrative small-model rates of $0.15 input and $0.60 output per million tokens, one call costs (2,000 × 0.15 + 250 × 0.60) / 1,000,000 = $0.00045. At the large-model rates of $2.50 and $10.00, the call costs $0.0075. Five such calls cost $0.0375.

Multiply those unit costs by 14,700 simple turns and 6,300 complex turns. Add $1.05 for 21,000 router classifications at $0.00005 and $1.35 for 15,000 input checks at $0.00005 plus 6,000 output checks at $0.0001. The total is $245.265, reported as about $245 or 49% of budget. Simple turns come to $6.615, shown as $6.62 in the table. Cache hits cost no generation tokens in this model, but still require gateway infrastructure and safety processing.

Without caching or routing, 30,000 five-call large-model turns cost $1,125, or 2.25 times the cap. Complex turns are 21% of all traffic and about 96% of this modelled spend. Increasing their share of misses from 30% to 40% raises daily spend to about $323. Holding all rates and proportions constant, $500 buys roughly 61,000 turns. That is a sensitivity estimate, not a capacity promise.

4. Trace components and failure ownership

The source diagrams show the same request path in several arrangements, with a versioned control plane above it. Read them as one system rather than competing designs. The control plane holds guard rules, banned phrases, routes and thresholds, prompts, provider and residency registry, budgets, pacing and red-team versions. Bad configuration must roll back atomically rather than leave half the workers on unsafe policy.

Authentication and rate limits reject unauthorised traffic before it can spend money. The microsecond rule guard blocks injection patterns and masks PII. Cache lookup follows masking. A cache failure becomes a miss. The token check rejects oversized calls. The complexity router chooses a capable model, defaulting to a safe route on failure. The LLM intent guard may be skipped only for policy-approved low-risk, previously seen patterns.

Every agent call reaches the spend ledger and pacer. Adapters wrap providers in deadline-bounded retry and a breaker. If A fails, B receives a portable prompt and tool schema. If both fail, the edge responder labels degradation or hands off. Output rules always validate PII and banned content, with a semantic check for risky replies. A cache write occurs only after output validation passes.

The ordering phrase screen, meter, route, recover describes responsibilities rather than permission to make an unmetered router or guard call. All paid classifier, guard, retry and fallback calls need admission too. The control-plane table and figures preserve the original component responsibilities and failure modes. Telemetry writes asynchronously with request traces, metrics, JSON events, cost tags and model tags.

5. Validate before shipping configuration

Exercise the actual authenticated endpoint, rate limits and guard path with the versioned red-team suite. Test a primary outage, fallback quota exhaustion, both providers unavailable, cache outage and each budget threshold. Verify that a region-bound request never escapes its pool, including during recovery. Confirm a model-face typed failure cannot be mistaken for a successful tool response.

Use labelled traffic to compare routing cost with misrouting and resolution rate. Measure first-token and full-answer latency separately by route. Test PII redaction in cache, responses, logs and traces. Replaying a bad run must identify the prompt version, guard reason, selected model, retries and final outcome.

Ship prompts, policy and routes as versioned configuration with rollback. Keep the fallback warm with the source's illustrative 1% live traffic share and verify it can accept full-load quota before an outage. Technical deep dives

Examine mechanisms, alternatives, and operational consequences.

Rules, intent checks and streaming boundaries

Rules check regex patterns, length, schemas and banned phrases in microseconds without a per-model-call bill. They cannot recognise every paraphrase: “pretend the rules above never existed” may evade literal injection patterns. A small-model guard classifies the intent of the surviving text and can recognise that rephrase, while spending money and a few hundred milliseconds.

Run checks in both directions. Mask a customer's PII before forwarding input. Validate output because a model can repeat something the customer supplied two turns earlier. A clean current input cannot prove that conversation history is safe to disclose.

Moderation applies a fixed general harm taxonomy, including harassment, hate, self-harm, sexual content and violence. Category scores determine flags. The source reports that mild rudeness such as “you are very poor ha ha” passed its moderation test. Product guardrails separately enforce support scope and system-prompt secrecy. A moderation pass does not mean a product-policy pass.

Log a reason for every block, return a safe reply and retain evidence for security review. A source-reported research platform attacks its own public endpoint through the normal auth, rate-limit and guard path. Include custom vulnerabilities for narrow policy exceptions: an apparently reasonable exception can reveal exactly the fact an attacker asks for. Both rule and LLM defences remain probabilistic. Report measured residual risk rather than invent a zero-risk promise.

Exact and semantic caching have different mechanisms

An exact cache normalises the PII-masked query and hashes it into a lookup key. “What is Python?” and “Tell me about Python” remain different inputs. A class called SemanticCache that only hashes text still implements exact matching.

A semantic cache embeds the query into a vector and searches nearby stored vectors. A tuned similarity threshold decides whether a paraphrase can reuse an answer. A loose threshold can return mismatched or stale answers. Start with exact matching and introduce vector lookup only when observed traffic contains enough repeated paraphrases to justify its risk and operating cost.

Include tenant, user permission, document version and prompt version in the response key. Cache reusable FAQ responses, never live account answers. Changing a prompt or knowledge version deliberately invalidates prior entries. Invalidate on document, access-control list (ACL) or metadata changes. Freshness and permission checks still apply to semantic hits.

A sudden hit-rate drop is a reason to inspect keying, versioning, traffic mix and invalidation before adding capacity. Output validation precedes writes: a blocked answer must never become a future cache hit.

Classification, token admission and daily pacing

The router requests a structured simple-or-complex label from a small model. A schema constrains the label rather than accepting arbitrary prose. Choose a threshold on labelled real traffic. Sending a simple request to the large model wastes money. Sending a complex request to a weak route can reduce resolution. Compare the cost saving with the product's tolerated misrouting rate.

A token cap catches one oversized request or runaway context. A daily ledger catches many ordinary calls adding up. Use a real tokenizer for the pre-call count, then reconcile with provider-reported usage. The rough examples len(text.split()) × 1.3 and len(text.split()) × 4 // 3 are trend approximations, not reliable admission accounting.

The pacer responds before exhaustion. At 80% spent, tighten routing toward cheaper paths. At 95%, allow the small model and hand complex work to humans. At 100%, allow cache and handoff only. In this case, “raise the router threshold” means require stronger evidence before taking the expensive route. A plain hard cap that runs out at 4 p.m. cannot meet the customer availability goal.

Implementation caveat added for the teaching design: concurrent calls need atomic budget reservations for their bounded potential cost, followed by usage reconciliation. Otherwise several individually admitted calls can overspend the same remaining balance. Output-token caps, retry reservations and classification/guard spend belong in that reservation. The source describes pre-call caps and a live ledger but does not supply this concurrency protocol.

Retry, breaker, fallback and degradation

A retry handles a transient connection drop or provider rate limit. Exponential backoff with jitter spreads clients across time. Fixed intervals synchronise retries into a thundering herd. The source's general pattern allows three to four attempts, but interactive requests must obey a deadline instead.

The breaker wraps the retried provider call and remembers dependency health. The illustrative settings are failure_threshold=3 and cooldown_seconds=5.0. Closed admits calls. Open rejects immediately. After cooldown, half-open admits a probe. Success permits recovery. Without the probe, the breaker has no path back to healthy. Under flapping load, count failures over a sliding window and require more than one successful probe before closing.

Fallback sends work to an independent provider when retries run out or the breaker opens. Attribute every response to its actual provider and model to measure cost and quality drift. Portable prompts and tool schemas prevent a different tool-calling format from silently breaking the agent. Keep the backup warm, verify quota at full load, and distinguish provider 429 responses from your own gateway limits.

When neither provider can answer, the edge can return a labelled response seeded from safe cached context, or log a ticket for a person. The model face must return a typed error. Giving an agent a degraded prose string as if it were a real model answer can cause a refund or booking against stale information. Recovery also obeys residency and spend policy.

Three collisions inside the three-second target

The source estimates roughly 1 ms for the rule guard, 5 to 10 ms for cache, 200 to 400 ms for the router, 1 to 2 seconds for the main model and 1 ms for output rules. At the upper ends, 1 + 10 + 400 + 2,000 + 1 = 2,412 ms, or about 2.4 seconds. These are whiteboard durations rather than measured percentiles. Summing stage estimates does not establish an end-to-end p95.

A risky-output LLM check adds 300 to 500 ms, reaching about 2.9 seconds. An additional serial input guard at an assumed 300 to 500 ms reaches about 3.4 seconds and breaks the target. Router and input guard read the same masked input, so they can run in parallel: their contribution becomes the slower duration. Skip the LLM input check only for policy-approved low-risk, previously seen patterns.

Five sequential model calls at 1 to 2 seconds take 5 to 10 seconds. Because complex turns are 21% of traffic, p95 full-answer latency lands inside the slow population. Agree first-token measurement for agent turns. Parallelise independent read-only tool work, and send common intents through a one-call workflow or router where an agent adds no value.

Backoff of 0.3, 0.6 and 1.2 seconds spends 2.1 seconds before attempt four even starts. Attempt timeouts make it worse. Give each interactive request a deadline, permit one retry only when enough time remains, then fail over. Once open, the breaker skips A immediately. The earliest affected callers still pay detection and timeout cost, bounded by the trip policy.

Streaming creates another boundary: a validator cannot retract words already displayed. Run rule checks sentence by sentence before release. Buffer risky replies, including refunds or account data, until the LLM output check finishes. Reconcile that buffering with the first-token target rather than claiming both unconditional streaming and complete pre-display semantic review.

Trace enough state without copying PII

Structured logs explain one request, metrics count outcomes across traffic, and traces identify the stage that caused a silent wrong answer. A successful HTTP status is insufficient evidence of a correct support response.

Retain these source trace fields: tenant_id, feature, prompt_version, model, input_tokens, output_tokens, estimated_cost, latency breakdown, retrieval top-k, reranker used, cache status, tool calls, retries, timeout status and final outcome. Add the provider, guardrail decision and block reason. Retrieval fields apply when a request actually uses retrieval, rather than implying every gateway call does.

Redact before writing. Copying raw prompts into logs duplicates PII outside the answer validator. Sample successes, keep every failure with safe redacted detail, assign retention and write asynchronously. Synchronous logging can cause a post-deploy latency jump. Restricted requests require equally restricted traces, including their storage backend.

The dashboard has six signals: daily spend against the pacing line, p95 first-token latency, fallback rate by provider, breaker state, guard block rate by rule and cache hit rate. Spend changes start with route and prompt version. Hit-rate changes start with key/version/traffic/invalidation. Fallback changes start with provider health, quota and breaker decisions. The source points to Observability and Production Diagnosis for replay and cost-spike investigation. Those linked chapters were not captured here.

Constrain the provider pool before failover

The underlying tutorial explicitly leaves residency unresolved when no third-party provider can receive the customer's data. The captured gateway case develops its suggested in-VPC or self-hosted model path. A virtual private cloud (VPC) is the customer's isolated cloud network.

At the edge, policy and PII findings assign a data class. Each class maps to an allowed pool before routing. Public content can use approved providers. Maskable PII must be masked before leaving the network. Region-bound data requires an in-region endpoint with contractual no-retention or a model in the customer's VPC. Data forbidden to leave the network stays on a self-hosted model there.

Give each restricted pool its own recovery path: another in-region endpoint, another self-hosted replica set, or human handoff. Falling back to a global pool violates residency even if it restores an answer. Logs and traces follow the same boundary. The source notes that its worked tracing examples are hosted, leaving a self-hostable backend as implementation work.

Self-hosting changes token spend into GPU-hour capacity. The source sizing formula is Replicas = ceil((QPS × Tokens_request) / (TokensPerSecond_replica × UtilizationTarget)). Queries per second multiplied by tokens per request gives token throughput demand. Divide by sustainable throughput per replica at the target utilisation, then round up. If the resulting count exceeds available hardware, reduce or reshape workload rather than assume more hardware exists.

An in-network model may be weaker and slower than the frontier route. Complex work may need earlier handoff and the $500 ceiling becomes a GPU-hour budget. The source references LLM Inference Serving for batching and failover and the air-gapped case for disconnected environments. Those chapters are outside this capture.

Residual failure modes and next changes

Prepare five residual failures: an injection that defeats both guards, correlated provider degradation, hidden quality loss from pacing, stale cached answers and PII leaking through logs. Each needs its own observation and recovery, as the table shows.

Extend output policy to tool calls and grant tools least privilege after an injection incident. Choose an independent third provider or an internal model for shared-upstream failures. Alert on pacer changes and compare resolution by route. Include versions and invalidation in cache policy. After a leak, audit response, cache, trace and log paths rather than checking the answer alone. None of these additions proves the next attack or outage impossible.

0 of 7 reasoning checks covered.

Why must the gateway sit under the agent’s model calls, and not only in front of the customer’s message?

The source estimates 5 to 20 sub-requests per agent turn. An edge-only gateway misses later paid calls and cannot retry or fail over them. Route every model and evaluator call through the model face, while the edge face screens customer-facing input and output.

Price the day aloud.

14,700 × $0.00045 = $6.615 for simple turns. 6,300 × $0.0375 = $236.25 for five-call complex turns. Router $1.05 plus guards $1.35 gives $245.265, or about $245. Complex spend divided by total is about 96%. All rates and mix are historical illustrations.

What does the naive design cost?

Without cache or routing, all 30,000 turns make five large-model calls. Each turn costs 5 × $0.0075 = $0.0375. Daily cost is 30,000 × $0.0375 = $1,125, which divided by $500 is 2.25.

Why does the input guard run before the cache?

It blocks known injection attempts and masks PII before lookup. The key therefore uses masked text. Output validation must also pass before writing a response, preventing a blocked answer from being reused.

Why is a class named SemanticCache in the source not semantic?

It hashes normalised text into exact keys. The two Python paraphrases have different hashes and miss. Semantic lookup needs embeddings, a similarity search and a tuned threshold, while still enforcing permission, version and freshness boundaries.

What is the difference between a per-request cap and the pacer?

The cap rejects one oversized call before spending. The pacer watches the day’s accumulated spend. At 80% it tightens expensive routing, at 95% it permits the small route and complex handoff, and at 100% it permits only cache and handoff. Provider usage reconciles the ledger after each admitted call.

Order the resilience chain and say what each link handles.

Retry handles a transient blip with deadline-bounded jittered backoff. A breaker wraps retried calls and remembers an unhealthy provider. Fallback chooses another policy-allowed provider. Degradation supplies labelled customer help or handoff after no provider remains. The model face returns a typed failure.

Why does the model face return a typed error rather than a degraded string?

An agent could treat an approximate degraded reply as reliable model state and issue a refund or booking at a stale price. The typed error forces the workflow to handle failure explicitly. A human can receive labelled degradation or a ticket handoff at the edge.

Sum the common-path latency.

Using upper estimates, 1 ms rule guard + 10 ms cache + 400 ms router + 2,000 ms model + 1 ms validator = 2,412 ms, about 2.4 s. A 300 to 500 ms output check raises this toward 2.9 s. These stage estimates require end-to-end measurement before making a p95 claim.

Why can p95 full-answer latency never be under 3 s here?

Under the stated five-sequential-call assumption, complex turns take 5 to 10 s and form 21% of all turns. The fastest 79% cannot cover the 95th percentile. Agree first-token measurement for multi-step turns, or change the workflow/mix rather than promise an impossible full-answer SLO.

Why can’t a typical retry schedule run on the interactive path during an outage?

The waits 0.3 + 0.6 + 1.2 total 2.1 s before attempt four, excluding failed-call timeouts. Use a request deadline, retry only with sufficient remaining time, and let an open breaker skip the failed primary. Failover must still fit within that deadline.

A region-bound customer’s primary provider goes down. Where does traffic go?

Choose another endpoint in the same allowed region or a permitted in-network replica pool. If neither can answer, hand off. The global pool remains forbidden. Apply the same restriction to traces, cache and logs.

What is the cost card’s 60-second line?

Complex agent turns dominate spend at 96% of the illustrative total. Route fewer suitable turns there, cap agent steps and use a one-call workflow for common intents. Cache only safe answers. Measure cost per resolved conversation and resolution by route, since reducing per-request cost can increase failed or repeated conversations.

Recall the admission and recovery boundaries

The edge face protects customer-facing input and output. The model face sees every one of an agent's 5 to 20 potential sub-requests. Screen, meter, route and recover, with a trace across every step.

Under the captured assumptions, 30,000 turns become 9,000 cache hits, 14,700 small calls and 6,300 five-call large turns. Spend is about $245 against $500. Complex work consumes about 96%. A 40% complex miss share raises it to about $323, and the unchanged mix binds near 61,000 daily turns.

Rules precede paid intent checks. Exact cache lookup starts with masked text and tenant, permission, document and prompt versions. Semantic lookup requires embeddings and a threshold. Validate outputs before cache writes. Admit calls before spending, pace at 80%, 95% and 100%, then reconcile usage.

Retry handles a blip, a breaker remembers bad dependency health, fallback selects another permitted provider and degradation supplies the human-facing floor. Machines receive typed errors. The illustrative breaker trips at three failures, probes after five seconds and needs half-open recovery. Keep fallback prompts, tools and quota usable.
