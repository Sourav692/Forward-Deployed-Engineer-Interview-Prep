# Learn UX: Breadcrumbs, Copy Deck, Wireframes and Dashboard

Date: 5 October 2026. Phase 1 tasks UX-03, UX-04 and UX-06 of `2026-10-05-production-implementation-plan.md`, built in FE-06 to FE-09. The copy below is the source of truth for wording; the code copy lives in `site/src/components/learn/copy.ts` and must stay in step with this file.

## Breadcrumb rules (UX-03)

The trail follows the curriculum: **Learn › Track › Section › Module › Lesson**. The component is `Breadcrumbs` in `site/src/components/learn/Breadcrumbs.tsx`.

| Page | Trail | Current page (no link) |
|---|---|---|
| `/learn` | none (area level) | — |
| Track | Learn › T5 AI Systems Design | Track |
| Module | Learn › T5 AI Systems Design › Casebook › T5.5 Scenario library | Module |
| Lesson | Learn › T2 … › Retrieval › T2.4 Retrieval: hybrid, rerank … › Lesson title | Lesson |

- Labels: tracks and modules show code then title ("T2.4 Retrieval: hybrid, rerank, query transformation"); sections show their title only; lessons show the lesson title.
- Links: every crumb but the last is a link. The section crumb links to the track page with the section anchor (`/learn/<track>#<section>`), because sections have no page of their own.
- Semantics: `nav[aria-label="Breadcrumb"] > ol`; the last crumb carries `aria-current="page"`; separators are decorative SVG chevrons (`aria-hidden`).
- Truncation at 375 px (below the `sm` breakpoint, 640 px):
  - Learn and the immediate parent always show. Every crumb between them collapses into a single "…".
  - Ancestor labels are capped at 10rem (14rem from 640 px) and end in an ellipsis.
  - The current page takes the remaining width and truncates last.
  - The trail never wraps and never causes horizontal scroll.

## Copy deck (UX-06)

British English. Titles in title case with the serial comma. Buttons start with a verb. Errors say what happened and what to do.

### Gap states

| State | Where | Copy |
|---|---|---|
| Partly ready | After the published lessons on the module page | **Partly ready.** The lessons below are published. The rest of this module is still being written. Coming soon in this module: {gapNote} |
| Coming soon | Under the module header; no lesson list | **Coming soon.** This module has no lessons yet. The objective and scope below say what it will cover, and the related modules teach part of it today. |
| Coming soon, no related module | End of page | No other module covers this topic yet. Check back after the next content update. |
| On hold | Under the module header; no lesson list | **Paused, will return.** This module is paused while its material is reworked. It will return; until then, the related modules below cover the nearest ground. |

Rules: on-hold pages never show `holdNote` or any repository path. Coming-soon pages do not show `gapNote` (it is written for the owner, for example "Nothing in the repository teaches SQL"); partly-ready pages do, because it names what is coming.

## Dashboard (UX-07)

Date: 10 October 2026. Phase 2 task UX-07, built in FE-16. The dashboard is empty-first: a new learner's first visit has no data, so every widget is designed for "nothing yet" before "populated". Nothing on these pages may show a number derived from data the learner never entered.

### Rules (owner decisions, 10 October 2026)

**Interview readiness.** Four inputs, weighted as in `rules.ts` `interviewReadiness`. An input is either measured (a value 0–100) or **not measured**; an unmeasured input is never counted as 0.

| Input | Weight | Measured from | Measured when |
|---|---|---|---|
| Worksheet and rubric scores | 35 % | Mean of every scorecard row scored on the live worksheet pages (`fd:v1:scores:*`, levels 1, 3 and 5), mapped with `rubricToPercent(mean, 5)` | At least one row is scored |
| Mock interviews | 30 % | For each of the five scenario mocks, the mean of the latest full round, or of the latest short round when no full round exists (`fd:v1:learn:attempts:mock:*`, FE-15), mapped with `rubricToPercent(mean, 5)`. Averaged over all five; a mock not yet taken counts 0 | At least one mock round is scored |
| Checkpoint pass rate | 20 % | Of the module checkpoints taken (`src/lib/checkpoints.ts`, DATA-10), the share whose latest attempt passed at 70 % (`checkpointReadiness`) | At least one checkpoint is taken |
| Behavioural readiness | 15 % | Across every question in the seven competency worksheets (`/modules/14-behavioural-and-leadership-round/*`, `fd:v1:answer-statuses:*`): Practised counts half, Mastered counts one, divided by the number of questions | At least one question is Practised or Mastered (opening a worksheet stores Not started for every question, which does not count) |

- **Overall score** = the weighted mean of the measured inputs, with their weights rescaled to 100 %. Shown as "{score} % · based on {n} of 4 inputs". With no measured input, there is no score.
- **Weakest input** = the lowest measured input. It gets the remedy link below. An unmeasured input is listed as "Not measured" with its own next step, never as the weakest.
- Portfolio readiness is not shown in Phase 2: none of its inputs (capstone rubric, projects, write-up) is recorded yet.

| Input | Remedy link |
|---|---|
| Worksheets | Case-study worksheets module (`/interview/case-study-worksheets`) |
| Mocks | The first scenario mock not yet taken, else the one with the lowest mean |
| Behavioural | The competency worksheet with the fewest questions practised |
| Checkpoints | The first checkpoint not yet taken, else one whose latest attempt failed (module page `#checkpoint`) |

**Next up.** One item, with the reason in one sentence. First match wins:

1. A module in the revision queue that the chosen path flags required or recommended (or any module in the queue when no path is chosen).
2. With a path: the path's start module when nothing is read yet; otherwise the first module in curriculum order that the path flags required, then recommended, that is not completed or skipped and whose prerequisites are met.
3. Without a path: the module with the most recent activity that is in progress.
4. Nothing matched: no next-up card; the empty state's actions take its place.

**Revision queue.** Modules whose effective confidence is 2 or less (`revisionReason`): rated 1 or 2, or faded there, since a rating drops one level for every 21 days without a new one. "Review now" opens the module page at its confidence control (`#yours`); rating 3 or more removes the item. A module with a checkpoint (DATA-10) also enters the queue when its latest attempt failed, or when a pass is due for a re-check (14 days after the pass, or 30 days after a confidence rating of 4 or more given since the pass); those items open the checkpoint (`#checkpoint`). Order: failed checkpoint, low confidence, faded confidence, re-check due; then oldest first.

**Finish by.** Only with a chosen path: remaining minutes = unread lessons in the path's required and recommended modules; `finishBy(remaining, weeklyHours, now)`. Weekly hours come from the path choice and are changed in Settings.

**Track progress.** Every Learn track with at least one lesson read: share of its published lessons read. No row for untouched tracks.

## Path diagnostic (UX-05): for owner review

**Status: awaiting owner review** (plan assumption A2, task PM-04). The questions, answers, weights and path copy are product copy ported from the prototype (`src/demo/data/paths.ts`) and adapted to the production curriculum. The code copy lives in `site/src/lib/paths.ts`; change both together. `npm run check:paths` validates the data.

Scoring: each answer adds points to one or more base paths, and the highest total wins. Ties go to the broader path, in the order Forward Deployed Engineer, Experienced Software Engineer, Data Engineer, ML Engineer, Architect or Consultant, Beginner, Revision.
