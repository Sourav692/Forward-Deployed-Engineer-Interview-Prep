# Choose a Reading Path

*Reading everything in order gives the complete picture but delays the material a role is judged on, so pick the path that matches the next round.*

◷ 4 min

Reading everything in order is one path, not the only one. Pick linear, by role, or by question, using the levels from [How the Material Is Built](01_How_the_Material_Is_Built.md) as the map.

**Objectives:**

- choose between the linear, by-role and by-question paths;
- say why the FDE path reaches system design and delivery before deep technical topics;
- check what to bring before starting.

---

## Read Linearly When the Field Is New

The linear path starts at orientation and ends with telling the story of a project. The source estimates roughly 35 to 45 hours of reading and interview practice. Choose it for a field that is new, or for the complete picture.

Its cost is time. A linear reader meets chunking strategy long before scoping, even when the next interview opens with scoping.

## Reorder by Role When an Interview Is Close

The by-role path skips nothing essential. It reorders the material so each role's core topics arrive sooner. The three roles are covered in the FDE role module; each has its own core set.

The FDE path is the clearest case. It goes to system design and to delivery before the deep technical topics. An FDE's first day is a scoping conversation, not a chunking strategy, so the path mirrors the job.

## Search by Question When the Gap Is Specific

Sometimes the gap is one question: "How does ABAC differ from RBAC?" or "When is multi-agent justified?" Go straight to the glossary, which links each term to the lesson that explains it. Read that lesson and its checkpoint, then stop.

> **Warning: a by-question reader still owes the prerequisites.** A lesson assumes the one before it. If its checkpoint feels unfamiliar, step back one lesson rather than pushing on.

## Prepare Three Things Before Starting

Bring comfort with reading Python: dataclasses, type hints and a `while` loop, for following the companion code. Having called an LLM API once helps, but the interview-prep sequence does not require it. For the final level, bring a real project. The storytelling material is far more useful applied to something actually shipped.

The runnable code is not copied into this repository. Interview walkthroughs and production-architecture references sit in a hands-on labs module. Broader implementations live in the companion course, at one pinned revision.

## Worked Example: Three Candidates, Three Paths

A career-changer with eight weeks and no LLM experience reads linearly. They need every plateau in order.

An AI engineer with a forward deployed loop in ten days reads by role. They move system design and delivery to the front and read the deep technical topics they already know last.

A candidate who keeps stumbling on one question about access control reads by question. They use the glossary, read one lesson, and answer its checkpoint.

Each path covers the same material. Only the order changes, and the order should follow the next round.

---

## Key Takeaways

- Read linearly, about 35 to 45 hours, when the field is new or you want the whole picture.
- Read by role when an interview is close; the FDE path puts system design and delivery first.
- Read by question for a single gap, through the glossary, and step back a lesson when a checkpoint feels unfamiliar.
- Bring Python reading skills, ideally one LLM API call, and a real project for the final level.
